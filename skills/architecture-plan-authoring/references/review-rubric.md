# 架构规划审查量表

用于高风险、跨团队或需要现场汇报的成稿。它是判断工具，不是机械打分表。

## 零、汇报合同与文字预算

- 是否已经由用户明确汇报对象、希望达成的目的和有效讲述时长？
- 若整场会议包含问答，预算是否只使用连续讲述时间，而不是会议总时长？
- 是否在写作前记录正文目标和硬上限？
- 是否先分配各章节的讲述分钟数，再换算章节字数？
- 实际正文是否低于硬上限，并避免通过大表格或图中文字隐藏超额正文？

三项汇报信息缺失时，不开始完整写作；正文超过硬上限时，优先迁移细节到图和附件，不通过压缩句子制造更高阅读密度。

## 一、叙事与讲述

- 能否用一句话说明这份文档希望听众最终认同什么？
- 一级标题能否自然组成一段“因为—所以—如何证明—需要什么”的故事？
- 作者能否只看标题和图，在有限时间内讲完？
- 按正常语速试讲时，是否在预算时间内结束并留有自然停顿？
- 听众是否在理解问题之前就被迫记忆缩写、路线编号或 Gate？

若前三项不能回答，优先重构主线，不做局部润色。

## 二、受众与语气

- 文档是否以目标听众已有的知识为起点？
- 说话姿态是提出经过调研的判断并邀请合作，还是单方面发布规则？
- 对合作方的要求是否先解释价值、输入和产出，再出现责任安排？

## 三、信息层级

- 正文中的每一段是否直接推动核心判断？
- 被 challenge 才需要的数字、完整矩阵和边界条件是否已移入附件？
- Gate、RACI、资源表是否在方案形成共识后出现？
- 一个章节是否同时引入过多框架、缩写或编号体系？

预警信号包括：正文体量突然成倍增长；表格远多于案例和关系图；同一页反复出现“不得、必须、未签、降级、N/A”；主语从业务和模型变成工作包与审批流程。这些不是绝对错误，但通常意味着文种发生了漂移。

## 四、技术可信度

- 关键技术判断是否有论文、实验、历史数据或业务案例支撑？
- 证据是否真正支持对应结论，是否清楚写出不能证明什么？
- 事实、推断、Proposal 和 TODO 是否可区分？
- 方案能否向前追溯业务需求，向后落到实验与验收？

不要为了防御 challenge 把全部证据塞进主流程。正文保留证据结论和最关键锚点，完整证据矩阵放附件。

## 五、图表有效性

- 是否先形成了覆盖核心故事的视觉骨架，而不是写完正文后才补图？
- 整组画板是否统一使用同一套三色体系（默认白色 `#FFFFFF`、深蓝 `#0055A4`、浅绿 `#DCF4A2`，或团队品牌色），并保持底色为主、主色聚焦、强调色少量？
- 业务问题、技术判断、目标架构、数据或训练闭环、路线与验收中，相关部分是否已有视觉锚点？
- 三项以上关系、三步以上流程、多分支和多层边界是否优先用图表达？
- 是否错误地用大表格替代架构图、流程图、闭环图或路线图？
- 图和正文是否互补，而不是重复？
- 多张图能否按顺序组成一条完整故事，而不是各自独立？
- 是否保留真正需要被讨论的 Schema、协议或代码示例？
- 图的标题是否直接表达结论，而非只写对象名称？
- 在目标平台允许时，图是否保持可编辑，而不是全部退化为截图？

## 六、画板独立阅读测试

把画板当作脱离正文传播的一张截图，逐张检查：

- 标题是否直接给出结论，而不是只有主题名称？
- 只看图能否理解输入、发生了什么、输出或关键影响？
- 是否存在正文未定义的缩写、内部代号、阶段编号或英文黑话？
- 必要术语是否在图内给出“实际做什么”的最短解释？
- 节点是否优先用动作与结果命名，而不是只写抽象组件名？
- 知识背景最少的目标听众是否仍能复述这张图？

未定义术语数量必须为零。发现术语问题时，优先换成普通中文或补充短定义；不要通过增加长段说明把画板变成文字墙。

## 七、Theory of Mind / 零上下文文档测试

测试时隐藏聊天记录、作者解释、中间草稿和旧版本。审阅者只能读取当前主文档及正文明确链接的附件。先做知识依赖检查：

- 项目专有概念、缩写、阶段名、坐标轴和分类标签是否全部先定义、后使用？
- 正文是否遵循“基本前提 → 定义与规则 → 分类映射 → 分析方法 → 结果 → 结论与行动”的依赖顺序？
- 每个关键数字首次出现时，是否能找到分母、来源、计算方法和证据性质？
- 表格与图的标题、表头、图例是否足以解释标签和读法，还是依赖作者口头补充？
- 最近删除或移动的内容是否带走了后文仍依赖的定义、单位、来源或映射关系？
- 是否出现“我们之前讨论过”“如前所述”但当前文档找不到对应内容的隐性引用？

然后让不了解项目的审阅者只读主文档，并回答：

1. 业务为什么现在需要这项能力？
2. 当前方案缺什么？
3. 提案最核心的技术判断是什么？
4. 第一期做什么，为什么不是其它范围？
5. 如何证明成功？
6. 需要自己所在团队配合什么？

若审阅者在首次遇到术语、阶段或数字时必须向作者追问，说明文档借用了作者记忆；若只能复述流程和术语，却说不出上述答案，说明文档“信息完整但沟通失败”。任何一项失败都应回到首次缺失定义的位置修复，而不是只在文末补充说明。
