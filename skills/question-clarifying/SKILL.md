# 问清问题（Question Clarifying）

大部分“AI 答得不好”其实是问题没问对：提问者嘴上问的和心里想解决的不是一回事，上下文也没给够。本技能的产出**不是答案，而是一个更值得回答的问题**。

## 什么时候用

- 用户的困惑里混着现象、猜测和情绪，看不出要解决什么；
- 用户连续换问法，说明问题本身还没稳定；
- 用户要一个重大判断，但没给约束、目标和已知事实；
- 用户明确说“先别给建议”。

不要用在：事实性查询、已经问得很清楚的具体问题、以及用户已锁定选项只差决策的场合。用户已经很清楚要什么时反复追问是骚扰，不是严谨。

## 执行方式

### 1. 一次只问一个问题

按“问 → 用户答 → 简短反馈 → 再问下一个”的节奏走。**不要一次抛出整套问卷**，也不要在用户回答前预告后面所有问题。主问题总数控制在 6 个以内。

### 2. 每次提问前先亮出自己的更新

用一句话说明上一条回答让你改变了什么判断（例如“原来我以为卡在实现，你说的时间线让我改判卡在验收口径”）。这一步不是礼貌，而是把推理暴露出来让用户能纠正。

### 3. 全程给用户的话分类

对用户说的每一条，判断它属于哪一类，并在必要时当面点破分类错误：

| 类别 | 特征 | 追问方向 |
| --- | --- | --- |
| 可验证事实 | 有来源、有数据、可复现 | 来源是什么、时间和样本是什么 |
| 对事实的解释 | 因果、归因、机制说明 | 有没有别的解释、如何区分 |
| 价值判断 | 好坏、值不值、应不应该 | 按谁的标准、和什么对照 |
| 目标 | 希望实现的状态 | 达成什么算成功、什么时候要 |

### 4. 只问可能改变结论的问题

每个候选问题都先过一遍：知道答案会改变判断吗？不会就不问。**信息够了立刻停止，不必凑满 6 个。** 用户为凑数问题付出的耐心，比多问出的那点信息贵。

优先检查这几处：关键词是否含糊、默认了哪些前提、证据来自哪里、有没有相反解释、结论成立与不成立分别意味着什么。

### 5. 收敛成结构化输出

问诊结束后给出：

1. 用户最初问的问题（照原话）；
2. 用户真正想解决的问题；
3. 已确认的事实；
4. 仍未验证的假设；
5. 最可能改变结论的关键变量；
6. 一个准确、具体、可继续行动的新问题。

### 6. 等确认再回答

**新问题必须经用户确认。** 确认后才给判断、理由和下一步行动；用户否掉或修正新问题时，回到第 1 步继续问，不要绕过确认直接开始解答。

## 验收标准

- 新问题比原问题更具体，且用户看了会说“对，我要问的是这个”；
- 未验证的假设被单列出来，没有混进“已确认事实”；
- 全程没有出现一次多问并发的问卷式提问；
- 结束时用户手上有一个能直接拿去执行或继续提问的句子。
