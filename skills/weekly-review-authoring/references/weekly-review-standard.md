# 周报写作标准

> 用途：起草或实质性复核周报时读取
> 核心目标：推动工作做出成绩，并持续沉淀可转成简历、晋升和项目复盘的职业证据

## 1. 内容优先级

周报内容按以下顺序取舍：

1. **工作结果**：完成了什么、解决了什么、形成了什么可复用产物、产生了什么影响；
2. **工作推进**：当前状态、关键取舍、依赖、下一步与判断门槛；
3. **卡点与支援**：浪费了多少时间或阻碍了什么结果，需要谁提供什么具体帮助；
4. **长期职业资产**：未来是否能直接改写为简历、述职或项目复盘材料；
5. **经验与组织信息**：仅在能改变行动、提升协作或帮助复用时保留。

篇幅冲突时，先保留结果、证据、影响、卡点和支援请求，再压缩背景介绍、过程感想和泛泛认知。

## 2. 结果写作单元

每项核心进展尽量覆盖：

- **目标**：要解决的业务或技术问题；
- **本人职责**：本人主导、负责或推动的部分；
- **关键动作与判断**：最关键的分析、实现、实验、协调或取舍；
- **产出与状态**：文档、代码、数据、实验、方案、机制或决策，以及完成/进行中/待验证状态；
- **证据**：数字、对比、代码位置、文档、实验记录、数据快照或可复现路径；
- **影响**：对效果、效率、质量、成本、风险、决策或协作的变化；
- **下一步**：闭环条件、成功门槛和停止条件。

避免只写“调研了、参加了、推进了、熟悉了”。如果结果尚未发生，用“形成方案/完成核查/建立基线/发现问题/设计实验”等准确口径，并说明还没有证明什么。

## 3. 六模块职责

下列字段名是本技能的默认模板。所在组织有自己的周报字段时，替换字段名、保留每一节的写作职责。

### Weekly OKR Progress【本周OKR进展】

- 先用一句话说明本周阶段和主线。
- 按重要性列核心结果，包含本人贡献、证据、影响、状态和下一步。
- 文档链接按业务/技术/工具等少量分类，不平铺成链接墙；链接前必须先说明文档解决了什么问题。

### Abnormity【异常】

- 写相对计划或正常状态发生的偏离、影响和处置。
- 没有异常时简短写“无”，不要为填字段制造异常。

### Obstacle【卡点】

对重要卡点尽量说明：

- 卡在哪里，持续多久或浪费了多少时间；
- 影响哪个结果、里程碑或判断；
- 已尝试的排查、绕行或降级；
- 缺少的信息、资源、权限、决策或协作；
- 希望谁在什么时间前提供什么支援；
- 无支援时的范围调整或止损方案。

聚焦事实、成本和解法，不归罪个人。支援请求必须可执行，避免“希望加强协作”一类空话。

### Refreshedness【知真】

全部使用 Bullet 的总—分结构：每个独立主题第一句直接给出核心判断，子 Bullet 补充证据、边界和行动启示。

常见主题包括但不限于：

- **论文/技术调研经验**：外部证据如何改变架构判断、实验或评测；
- **自动化工具经验**：个人小工具或工作流节省了什么成本，能力和边界是什么；
- **组织 Context 与 Agent**：现有信息怎样被整理、哪些事实底座仍需组织提供。

只写当周确有证据的主题。技术调研、工具和组织信息之间没有直接关系时必须拆成不同顶层 Bullet，不能强行串成一个闭环。

### Interaction【互动】

- 写与他人的具体协作、本人的推动、达成的结果和仍待确认的依赖。
- 区分“已确认”与“基于资料建立的初步地图”。
- 互动数量不是结果，协作带来的决定、输入、资源或风险变化才是。

### Action【决策】

- 写已经明确的取舍和后续动作。
- 尽量包含 owner、时间点、判断门槛和失败后的调整。
- 不把尚未得到确认的建议写成团队决策。

## 4. 简历可转化性

Review 每个核心结果时追问：

> 如果未来离开，这一条能否在不重新考古的情况下，改写成一条有技术含量、有结果证据的简历材料？

长期保留：

- 项目背景和问题规模；
- 本人职责与影响范围；
- 关键技术、架构、方法或协作机制；
- 为什么选择该路线；
- 可量化结果、前后对比、覆盖范围或风险降低；
- 代表性文档、代码、实验和数据路径；
- 从不确定到结论的关键判断。

未来转成外部材料时需要做保密检查、去标识化和口径重写。简历可转化不等于宣传化，更不能夸大尚未验证的业务影响。

## 5. 证据和归属

- 区分已验证事实、本人判断、他人输入和待验证假设。
- 数字注明口径和快照时间；变化快的事实保留最后核对日期。
- 不把团队已有文档、迁移件、旧稿或 Agent 未核对内容包装成本人新产出。
- 共同工作写清本人负责的部分。
- Agent 参与的产出可写为：本人提出问题、提供 Context、设定判断门槛并多轮校正，借助 Agent 完成资料整理或产物沉淀。
- 不因使用 Agent 抹掉本人的技术判断和交付责任，也不把 Agent 自动生成当成已验证成果。

## 6. 建议模板

```markdown
# 周报草稿（YYYY-MM-DD—YYYY-MM-DD）

> 状态：待本人 Review，未提交 OA / 在线文档
> 依据：本地工作记录、专项文档、实验与必要的只读资料
> 最后核对：YYYY-MM-DD

## Weekly OKR Progress【本周OKR进展】

本周处于……阶段，核心是……

1. **结果一**：目标、本人动作、产出、证据、影响、状态和下一步。
2. **结果二**：……

## Abnormity【异常】

- 无；或异常、影响和处置。

## Obstacle【卡点】

- **卡点结论**：影响、已做尝试、所需支援和止损方案。

## Refreshedness【知真】

- **独立主题一的核心判断。**
  - 证据或经验。
  - 边界或行动启示。
- **独立主题二的核心判断。**
  - 补充内容。

## Interaction【互动】

- **协作结果**：本人推动、对方输入、达成结果和未决依赖。

## Action【决策】

- **决策/动作**：owner、时间点、判断门槛和失败调整。
```

## 7. Review 清单

- 最硬的 1—3 个结果是否在开头可见；
- 是否写清本人贡献而不只是团队行为；
- 重要结论是否有证据、影响和状态；
- 卡点是否包含时间/结果成本和可执行支援；
- 是否至少有一项可直接转成简历或述职材料；
- 技术内容是否能被同行复核；
- `知真` 是否按独立主题拆分；
- 文档链接是否服务于结论而不是替代结论；
- 是否保留未验证边界；
- 是否仍处于本地 Review 状态，未被误写成已提交。
