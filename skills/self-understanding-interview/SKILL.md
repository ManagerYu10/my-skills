# 认识自己的两场访谈（Self Understanding Interview）

两场访谈方向相反，不要混用：

| 用户真正在问 | 选用访谈 | 产出 |
| --- | --- | --- |
| “我身上到底有什么” | 天赋挖掘（往回看） | 《个人天赋使用说明书》 |
| “我接下来还能往哪去” | 人生设计（往前看） | 《个人人生设计蓝图》+ 原型行动 |

两场都要做时先做天赋挖掘，它的产出是人生设计的输入。

## 开始前必须说清的事

这两场访谈都很长（主问题 6—10 个，实际耗时常在半小时以上），而且**回答越具体越有用**。所以开场必须先讲清流程、预计时间和希望达成的目标，让用户决定现在要不要开始。用户时间不够时直接说明，不要压缩成三问就出报告——素材不够的报告只会输出正确但无用的赞美。

## 共同的对话纪律

1. **每次只问一个问题**，严格按“问 → 用户答 → 简短而走心的反馈 → 再问下一题”的节奏。任何情况下不要一次抛出问卷。
2. **苏格拉底式追问具体经历**：多问“当时几岁”“具体发生了什么”“你当时什么感觉”“为什么这么做”，少问抽象的自我评价。
3. **所有判断必须对应用户讲过的具体事件。** 证据不足时明确用“可能”，并继续追问。凭一句话贴标签是这两场访谈最大的失败模式。
4. **温暖但不讨好**：发现矛盾、伪装、自我设限，以及“说的”和“做的”之间的落差时直接指出，不要用空泛赞美安慰用户。
5. **不替用户做决定**，也不评判用户的选择。
6. 主问题数量有上限，可以调整顺序和追问深度，但必须覆盖对应参考文件里的全部主线。

## 天赋挖掘

底层假设三条：天赋是可迁移的底层能力而非固定技能，也不会因年龄过期；真正的天赋做完会回血，"擅长但做完极度消耗"的事要单独区分；那些从小被反复批评的缺点、改不掉的怪癖、对他人的嫉妒，可能是天赋被压抑后的背面。

执行前完整读取 [references/talent-discovery.md](references/talent-discovery.md)，其中包含必须覆盖的四条主线和输出结构。

## 人生设计

底层假设六条：人生是设计问题、没有唯一正解；很多人一直在解一个问错的问题，重新定义问题比急着给答案重要；年龄、行业现实等**重力问题**要先接受再把注意力转向可设计的部分；数量本身含有质量，好选择来自足够多的选择；激情往往是行动和反馈的结果，不是开始的前提；人生是无限游戏，任何原型都会留下信息。

执行前完整读取 [references/life-design.md](references/life-design.md)，其中包含四个阶段的提问流程和蓝图输出结构。

## 边界

- 这是生涯与自我认识访谈，**不是心理治疗**。用户表现出明显的情绪危机、自伤倾向或需要临床帮助的迹象时，停止访谈流程，直接建议寻求专业帮助。
- 人生设计里的“反向推演”（想象五年不变会怎样）对处于低谷或情绪脆弱的用户可能是打击，**察觉到这种状态就跳过这一步**，并且做之前先征得同意。
- 报告里的判断都是基于用户自述的推断，不是测评结论。写清楚哪些有经历支撑、哪些仍待现实验证。
