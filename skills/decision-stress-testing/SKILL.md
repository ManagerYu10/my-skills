# 决策压力测试（Decision Stress Testing）

决策卡住通常不是选项不够多，而是两边理由都没被论证到最强，所以没法比较。本技能只做两件事：**把两边都论证到最强**，以及**在推演失效时把决策交给现实**。

## 先判断卡在哪一层

| 用户的处境 | 选用方法 |
| --- | --- |
| 两个选项都有道理，说不清到底差在哪 | 双向钢人论证 |
| 反复权衡但信息没有增加，越想越糊 | 最小实验替代空想 |

第二种更常见也更容易被忽略：**当再想一轮也不会产生新信息时，继续分析就是拖延。** 判断标准是问用户“再花两小时思考，会知道什么现在不知道的事吗”。

## 1. 双向钢人论证

“钢人”是稻草人的反面：不攻击对方最弱的版本，而是先替对方建出最强的版本。

### 执行顺序

1. **先重述选择本身。** 用最完整、有力的方式说清用户真正需要做的选择，不要默认用户已经把问题想清楚了——重述错了后面全白做。
2. **分别论证两个方向。** 每个方向都给出：最强理由、适用条件、最大收益、最大风险、以及最难回答的反对意见。两边的力度必须对称，不能一边三段一边一句。
3. **找出真正的分歧。** 明确写出双方的核心分歧点、最可能改变结论的关键变量、以及还需要补充的信息。
4. **只问一个问题。** 挑一个最可能改变结论的问题问用户，不要抛问卷。
5. **等回答后再下判断。** 给出明确判断、理由、适用条件和下一步行动。**必须给出明确判断**——把“两边都有道理”还给用户是失职。

### 与问清问题的区别

`question-clarifying` 用在还不知道该问什么的时候；本方法用在**已经有两个候选答案、只差选哪个**的时候。两者底层目的不同，不要互相替代。

## 2. 最小实验替代空想

### 执行顺序

1. **找出决定背后最需要验证的 3 个假设**，再从中选出最可能改变最终结论的那一个。一次实验只验一个假设。
2. **围绕它设计一个最小实验**，三条硬要求：低成本、可逆、能在用户可接受的周期内（默认 7 天）完成。做不到可逆就不是最小实验，是提前下注。
3. 实验方案必须写清：具体做什么、需要投入多少时间和资源、观察什么指标、**什么结果支持继续、什么结果提醒停止**、实验结束后能获得什么新信息。
4. **给出明天就能开始的第一个动作。** 第一步不具体到能立刻执行，这份设计就没用。

### 两个常见失败

- 设计了一个“做完还是不知道该选哪个”的实验——回到第 1 步，说明验的不是关键假设；
- 停止条件写得含糊（“效果不好就停”）——必须写成可判断的现象或数字。

## 通用纪律

- 两个方向的论证力度对称，不夹带自己的偏好；
- 关键变量单列，让用户能自己判断变量落在哪一侧；
- 未验证的判断标为假设，不写成事实；
- 用户已经明显倾向一边时，仍要把另一边论证到最强，再指出倾向所依赖的前提。
