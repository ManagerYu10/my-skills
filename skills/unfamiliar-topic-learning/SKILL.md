# 陌生领域学习（Unfamiliar Topic Learning）

“学不会”通常不是方法不够多，而是需求错配：想搞懂机制的人拿到了类比，想模仿范例的人拿到了概述。本技能第一步永远是**分清用户处在哪种需求下**，再用对应方法。

## 先判断需求，再选方法

| 用户的实际处境 | 选用方法 | 产出形态 |
| --- | --- | --- |
| “这个概念我完全听不懂” | 双层解释 | 小白版 + 专业版 + 术语对照 |
| “这个东西做得真好，我想学它” | 反向拆解 | 可复用规律 + 操作清单 |
| “我想系统搞懂这个领域/公司/技术” | 横纵分析 | 带来源的深度研究报告 |
| “这份材料里的说法是真的吗” | 事实核查 | 分级结论 + 推理漏洞 |

需求同时命中两条时按顺序做，不要把两种结构混成一篇。判断不了就问一句用户想拿这份学习结果做什么。

## 四种方法的执行要点

### 1. 双层解释：治“好像懂了”

**必须两层都给，且顺序固定。** 第一层小白版用生活化语言加一个具体例子；第二层专业版用准确术语讲清核心机制、适用边界和常见误解。

只给类比是本方法最常见的失败：用户记住了比喻，机制还是一团雾。所以结尾必须补三件事——小白说法与专业术语的对应关系、最容易理解错的地方、3 个用来检验是否真懂的问题。

### 2. 反向拆解：治“只会夸好”

先用一句话说明这个范例解决了什么问题，再解释它**为什么有效**，重点在拉开质量差距的关键选择，而不是罗列它有哪些功能。

必须回答：服务谁、目标是什么、用了什么结构或流程、哪些选择决定了质量、它的完成标准是什么、哪些规律可迁移而哪些只适合这个案例。最后给 3—5 条可复用规律、一份可照做的操作清单、一个最值得先试的小练习。

**区分可迁移规律和个案细节是本方法的核心价值**，混在一起就退化成了抄袭清单。

### 3. 横纵分析：治“资料堆砌”

两条轴：纵轴看它怎么走到今天，横轴看它今天和同类比差在哪。**只有两轴交叉才能看出历史选择如何演化成今天的能力和包袱**，单看任何一条都会得出漂亮但没用的结论。

- 纵向：诞生的背景与需求、关键推动者、重要转折与成败、哪些早期选择变成了今天的能力/路径依赖/包袱；
- 横向：选谁比较且说明为什么选它们、用统一维度比强项与短板、市场为什么选它又为什么放弃它；
- 合起来：过去形成的约束如何影响未来、未来最可能的 3 条路径、每条路径的前提和预警信号。

证据规则：优先一手来源（官方资料、原始数据、论文、财报、访谈）；重要结论就近标注来源与日期；事实、推断、观点分开写；信息冲突时并列呈现，找不到证据明确写“暂未核实”。

有联网深度研究能力时**必须开启**再执行本方法，否则只能凭训练数据作答，报告的“可追溯”承诺就是假的。

### 4. 事实核查：治“愚昧之巅”

先把待核查内容拆成三层：可被外部验证的事实、从事实推出的结论、其中夹带的价值判断。三层混着核查是无效劳动。

事实层联网核实来源、样本、时间和完整上下文，逐条标记为：已证实 / 基本成立但需收窄 / 存在争议 / 证据不足 / 明显错误。

再在“假设事实成立”的前提下检查推理：事实能否推出该结论、有没有未经验证的隐含假设、是否混淆相关性与因果、是否遗漏其他解释或关键信息、结论在什么条件下成立或失效。

输出必须包含**“我目前可以相信到什么程度”**——给不出这一条，核查就没有落地。本方法同样适用于核查他人的观点和方案，不限于数据。

## 通用纪律

- 事实、推断、观点分开写，任何方法都适用；
- 证据不足时写“暂未核实”，不要用流畅的表述补齐缺口；
- 用户给了原始材料就先读材料再作答，不要凭印象概述；
- 学习结果要给出自检问题或可执行动作，否则用户无法验证自己是否真的学到了。
