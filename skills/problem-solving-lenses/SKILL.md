# 解决问题的三种视角（Problem Solving Lenses）

方案质量的上限由**看问题的视角**决定，不由措辞决定。本技能提供三种换视角的方式，先判断该换哪一种，再按该方式的结构推导。

## 先判断卡在哪里，再选视角

| 卡点特征 | 选用视角 | 核心动作 |
| --- | --- | --- |
| 问题横跨多个专业，单一角度总有盲区 | 专家会诊 | 组互补专家团并让他们互相质疑 |
| 方案一直在打补丁，越修越复杂 | 第一性原理 | 拆回基本事实重新推导 |
| 本行业常规解法都试过且无效 | 跨领域借解 | 抽象结构后去别的领域找机制 |

信息不足时，**先只问用户一个最关键的问题**，不要一次抛出需求清单，也不要凭猜测直接给方案。

## 1. 专家会诊：让分歧浮出来

“你是一位有 20 年经验的世界级专家”这类单一身份设定解决不了跨专业问题。做法是选 **3 种真正互补的专业视角**，并说明每种为什么必要。

每种视角分别回答：它如何重新定义这个问题、它最推荐的路径、其他视角最容易忽略的风险、什么新证据会让它改变判断。

然后**让三种视角互相质疑**，这是本方法最关键的一步——真正的信息藏在分歧里，不在共识里。质疑要产出三件事：共同认可的事实、真正的分歧、分歧背后不同的假设。

最后综合输出：最推荐的方案、适用条件、最大风险、退出条件、第一步行动。

两条硬约束：

- **不要选三个高度相似的身份**（例如后端工程师、架构师、技术负责人），否则质疑环节退化成互相点赞；
- **不要模仿或编造真实人物的观点**，用专业视角，不用真人名义。

## 2. 第一性原理：治路径依赖

把问题拆回最底层，明确区分四类东西：

1. 已经确认、无法绕开的基本事实；
2. 习惯性接受却从未验证的假设；
3. 真正想实现的目标；
4. 现实中的资源与约束。

**第 2 类是本方法的全部价值所在**：多数“必须这样做”其实是没人验证过的行业惯例。识别出来后，暂时放下惯例和现成方案，只从基本事实、目标、约束重新推导可行路径。

输出：原方案中只在修补表面的部分、从基本事实重新推导出的新路径、这条路径成立的前提、验证它的第一步。

适合改组织流程、定产品架构、修复杂遗留系统。不适合已经跑得很好只需微调的东西——对能用的系统喊“推倒重来”是浪费，不是深刻。

## 3. 跨领域借解：扩散视角

第一性原理是往下挖，跨领域借解是往外看。先剥掉行业术语，把问题抽象成人类在别的领域也会遇到的形态，并找出：问题的底层结构、真正的核心矛盾、普通解法失效的原因。

然后从历史案例和**至少 3 个彼此距离较远的领域**中，寻找底层结构相似的问题。领域挑得太近（例如都在互联网内部）就借不到新机制。

每个案例都要说明：那个领域遇到了什么问题、用了什么解决机制、与当前问题相似在哪、哪些部分可迁移、什么条件下会失效。

最后选出最值得借用的 3 种机制，翻译成适合用户当前处境的方案，并推荐一个**低成本、可逆**的先行实验。

## 通用纪律

- 先换视角，后给方案；用户明确说“先别给建议”时严格遵守；
- 迁移必须带条件：写清什么情况下这套机制会失效；
- 每条方案都要给退出条件和第一步动作，否则只是一段议论；
- 不确定的部分标为待验证假设，不要写成结论。
